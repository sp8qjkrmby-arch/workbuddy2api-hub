# 规矩（红线与纪律）

## A. 上游 `CONTRIBUTING.md` 的硬性规则（我们照抄执行）

1. **提交文本**：主题简洁、`<type>(<scope>): 摘要`；正文中英双语。
2. **提交前必须完成冒烟门禁**（四项：服务能起、面板能开、**端到端真实上游请求成功**、隔离端口）。任一失败 → 先修再提交，不许以"CI 会跑"为由跳过。
3. 端口 8788 被占用时**不要停它**（可能是活跃会话），改用 8799 等隔离端口。
4. 不许弄丢别人的改动：解冲突"两边都留"；别用改测试来消红。

## B. 我们本地新增的红线

| # | 红线 | 为什么 |
|---|---|---|
| 1 | **不停 8788**（除非明确获批且走脱离会话的重启脚本） | 这个对话的模型请求也走它；硬停会打断自己 |
| 2 | **不在生产目录跑测试** | 探针测试会起真窗口/改注册表/真对话框，标题与生产进程同名 |
| 3 | **不改 `accounts\` 与 `usage\` 的结构与语义** | 它是 `release-manifest.json` 里声明的 `protected` 区 |
| 4 | **不把更新指向第三方仓库并保持自动安装** | 等于把可执行代码下发权交给陌生人 |
| 5 | **不删 `data\backups\core-*.zip`** | 唯一的内核回滚锚点 |
| 6 | **改载荷前：先过门 1，改完过门 1+门 2** | 见 `10-verification.md` |
| 7 | **不手工改 `data\shell.json` 后不重启** | 运行中的外壳会覆盖手改 |
| 8 | **不提交任何 token/密码/账号 JSON** | `.gitignore` 已挡，但别绕过去 |
| 9 | **写 `.ps1` 含中文必须 UTF-8 带 BOM；写 `.cmd` 必须 CRLF+ASCII** | 否则 5.1 / cmd.exe 解析炸（见 `14-gotchas-windows.md`） |
| 10 | **不在会话中途重启生产** | 用一次性计划任务延迟执行（见 `06-runbook-start-stop.md`） |

## C. 提交前自查清单

- [ ] 门 1 基线校验通过（`61 MATCH / 0 DIFF`）
- [ ] 门 2 全量测试通过（`261 passed / 0 failed`）+ `check_clean_checkout` clean
- [ ] 改了外壳或出包 → 门 3 冒烟通过
- [ ] 提交信息符合规范（中英双语、一件事）
- [ ] 没把 `accounts/`、`usage/`、`*.zip`、`__pycache__` 带进暂存区
- [ ] 新增模块记得登记进 `release/portable.txt`（否则 `_test_release_assets.py` 会红）

## D. 出问题时的处置顺序

1. 先**止血**（回滚到上一个可用状态：`data\backups\core-*.zip` 或 `git reset`）；
2. 再**定位**（三道门逐级排查，日志见 `09-logs.md`）；
3. 最后**记录**（写进 `maintenance/LOCAL-LOG.md`，并把新坑加进 `handbook/14-gotchas-windows.md`）。
