## 0. 一句话

给 `wb-proxy` 内核（v1.7.4）套的 Windows 外壳：**内嵌看板单窗口 + 托盘 + 开机自启 + 一键更新内核**，
内核一个字节都不改、外壳可更新、界面有降级链（WebView2 → 原生窗口 → 命令行）。
外壳源码在 `launcher\`，自带 `runtime\`（Python 3.14，含 tkinter 与 WebView2 依赖）。

**给新会话的开局提示词**（可直接粘贴）：

```
项目：给 workbuddy2api-hub 内核做 Windows 外壳，路径 C:\Desktop\wb-shell。
先读 README.md 和 交接文档.md，然后按交接文档 §2 做一遍只读体检并汇报现状，先不要改任何东西。
铁律：8788 上的内核正在承载本会话流量，不要重启/停止它；清理测试进程只能用
runtime\python launcher\kill_test_processes.py（默认预演）；内核目录 wb-proxy\ 只读。
```

## 1. 铁律（违反会直接打断用户）

1. **8788 别动。** 内核正承载用户当前会话的模型流量。任何"重启外壳/内核/装更新"都会短暂切断它，
   必须**先问用户**再动。历史上掉线两次都是因为这个。
2. **清理测试进程只能用** `runtime\python launcher\kill_test_processes.py`（默认只预演，`--apply` 才真动手）。
   **不要手写进程匹配** —— 历史上把生产 8788 误杀过两次。该脚本用「测试端口白名单 + 生产端口硬保护 +
   排除自身进程树 + 确切测试脚本路径」替代模糊匹配；临时目录按**确切名字**删（`%TEMP%` 下有别人的 `wb-*`）。
3. **内核零改动**：`wb-proxy\` 里的一切只读。`data\baseline-core-sha256.txt` 是只读基准，
   任何时候都能自证"外壳没改过内核"（§2 第 7 条）。
4. **会开真窗口的探针要先跟用户说一声。** `tests\probe_*.py` 里有好几个会创建真实 WebView2 窗口，
   **标题和应用完全一样**（`WorkBuddy2API-Hub 网关`）。用户会以为是程序自己开了窗口（真发生过）。
5. **`launcher --selftest` 会停掉"配置里那个端口"的内核**（默认 8788）。要自检必须显式给隔离端口：
   `runtime\pythonw.exe launcher --selftest --port 18788`。README §三/§五 已写明。
6. **`shell.json` 的 `panel_password` 有副作用**：一旦设置，外壳每次启动内核都会传 `--panel-password`
   → **等于把内核面板密码固定成它**（覆盖用户在看板里改的）。自动登录功能**没有复用它**，
   而是用单独的密封文件（见 §4.6），别把两者混起来。
7. **外壳改完必须重启外壳才生效**（内存里的旧模块）。判断"运行中的外壳是不是旧的"看 §2 第 6 条。

## 4. 交付了什么（2026-10-14 一整天；§4.11 是 10-15 补的）

每条都按「问题 → 改在哪 → 怎么验 → 代价/边界」写。

### 4.1 内核更新的"安装入口"（原来只有检查，没有安装）

* **问题**：`updater.py` 的 8 步更新链路早就写好了、也有测试，但**界面里没有任何地方能触发安装**；
  控制层与托盘的「检查更新」都只返回一句「安装入口在后续阶段接入」。
* **改**：`ui_web.py` 新增 `api_update_check` / `api_update_install` + `_push_update_progress`；
  注入层新增 `updateFlow → showUpdateDialog → 进度 → showUpdateResult`；托盘菜单新增「安装更新 vX.Y.Z」。
  安装**只认"检查"那一步存下来的 plan**，JS 只能传 `tag` 且必须对上（校验值/URL 不从界面收）。
* **验**：`tests\ui_api_test.py`（第 7 节，打桩）、`tests\probe_menu.py`（真实 WebView2 里的 DOM）、
  `tests\probe_menu_live.py`（真实检查更新，用内核文件指纹证明没装）、`tests\tray_autostart_test.py`（第 4.5 节）。
* **边界**：安装必然停内核（Windows 文件占用），所以"真装"从未在本机生产上端到端跑过（会断会话）。

### 4.2 更新成功后的三选一（用户点名要的"询问窗口"）

* **问题**：更新装完，界面里还是旧东西，用户不知道该怎么办；而且**版本号显示本身是坏的**（见 4.3）。
* **改**：成功后的结果面板给出三个选择 —— 「稍后手动」/「重新加载看板」（推荐，`api_reload_dashboard`）/
  「重启外壳（再停一次内核）」（`api_restart_shell` → 协调器 `request_shell_restart`）。托盘也加了「重启外壳」。
* **边界**：修了 4.3 之后，"重启外壳"**不是必需**的 —— 真正还旧的是**页面**（旧内核给的 HTML/JS）。
  文案里明确写了这点，不让用户白付一次中断。

### 4.3 内核版本号自刷新（"更新完还显示旧版本"的根因）

* **问题**：`service.py` 的 `core_version` **只在构造时读一次**，而 `status()` 是
  `health.get("version") or self.core_version`；这个内核的 `/health` 里**没有版本字段** →
  更新到 1.7.4 之后，底栏/菜单/「检查更新」的"当前版本"一直说 1.7.3，**连「检查更新」都会再次说有 1.7.4**
  （看起来像更新没装上去）。用户只能去重启外壳。
* **改**：`status()` **每次都重新确定**版本（`/health` 报了就用它，否则读盘）；`read_core_version` 加
  `(mtime, size)` 缓存（`status()` 每 0.5 秒被问一次，不缓存就是每半秒重读一遍内核源码）；
  内核启动日志加版本（`内核已就绪：账号 9 个（可用 9），版本 1.7.4`）。
* **验**：`tests\update_isolated_test.py` **场景 F**（同一个服务对象，改一下副本的版本串，`status()` 立刻跟上）。

### 4.4 下载护栏 + `install()` 重排（"更新报校验失败"的根因）

* **问题（真实故障）**：2026-10-14 两次更新都报「SHA256 校验不通过」，实测是**直链把 9.9 MB 的包
  切在 4.7 MB / 2.8 MB 处**（两次体积与哈希都不同）。根因：`_download` 只读到 EOF 就收工、**从不核对字节数**，
  半包被当成成功。而且老顺序是**先停内核再下载** → 那两次各白停了一次内核（下载实测要 60–90 秒）。
* **改**：`_download` 重写 —— **核对字节数**（少了就算失败）+ **断点续传**（带 `Range`，实测 GitHub 支持 206）
  + 最多 4 次、间隔 2/4/6 秒；补不回来时报「**下载不完整：x MB / y MB**」而不是含糊的"校验失败"；
  校验不过的消息里带上**包体积**并区分"体积也不对（下载坏了）"vs"体积对但内容不同"。
  `install()` 重排为：**下载 → 校验 → 解压 →（才）停内核 → 备份 → 覆盖 → 自检 → 回滚**。
* **验**：`tests\download_resume_test.py`（本地假服务"发一半就断"，14 项）、
  `tests\update_isolated_test.py` **场景 E**（运行中安装：下载时内核还活着，顺序实测 `下载0→解压3→停4→覆盖7`）。

### 4.5 镜像的校验值来源加固

* **问题**：配了 `update_mirror` 之后，**校验值也跟着走镜像**（`fetch_expected_sha` 给 URL 加前缀）——
  镜像能同时改包和 `SHA256SUMS`，"官方 SHA256 校验"就名存实亡。
* **改**：有镜像时**优先用官方 API 的 digest**（`api.github.com` 的响应不经镜像），来源如实标注
  「官方 releases 元数据 digest（镜像只用于下载包）」；只退到镜像的 `SHA256SUMS` 时会标成「镜像提供的」并附提醒。
* **验**：`tests\ui_api_test.py` 第 5.5 节（打桩：镜像给的校验值必须被忽略）。

### 4.6 「设置…」+ 记住面板密码（自动登录，本机 Windows 用户级 DPAPI 密封）

* **问题**：每次重开窗口都要输面板密码。根因有两层：token 存在页面自己的 **`sessionStorage`**，
  而外壳的 `×` 是**销毁窗口**（pywebview 拦不住关闭）、托盘「显示窗口」是**重建新窗口**；
  更要命的是 token 在**内核内存里**、**内核一重启必然失效**（内核注释原话：
  *"Deliberately not persisted: restarting the gateway logs browsers out, which is the safer default
  for a LAN tool that people expose behind a port map."*）。所以"记住"只能记**密码**。
* **改**：
  * 新增 `launcher\secret_store.py`：**Windows DPAPI（`CryptProtectData`，当前用户作用域）** 密封，
    密文存 `data\panel-password.sealed`，**不进日志**，换 Windows 用户/换机器解不开。
  * `ui_web.py`：菜单里「内核位置…」升级为 **「设置…」**，里面两节：① 内核位置（原样搬进来）
    ② 面板密码（要不要密码、是不是默认 admin、勾选框、忘记按钮、DPAPI 说明、代价提醒）；
    注入层 `panelTryAutoLogin`（`MutationObserver` 盯 `#panelGate`）→ 取口令 → 填 → 调看板自己的
    `submitPanelLogin()`；`panelHookLogin` 在**登录成功之后**把用户刚输的密码报给外壳（改过密码会自动顶掉旧口令）。
  * 后端三接口：`panel_status` / `panel_secret` / `panel_remember_password`
    （**开关关着时取口令一律拒绝**）；`service.probe_panel_status` 读内核那个**免登录**的 `/panel/status`。
  * 三条自律：不勾绝不记；加密存放；每个页面加载只试一次（内核限流 5 次/60 秒），失败退回手输。
* **验**：`tests\panel_secret_test.py`（DPAPI 往返 + 契约 + "不勾就不记" + "关开关连密文一起删"，

### 4.13 面板通知被外壳底栏挡住（用户第三次反馈）——2026-10-15

* **现象**：面板自己弹的提示（截图里是「设置已刷新」）在右下角被外壳底栏盖住一半。
* **根因（有据）**：面板的通知是 `dashboard.html` 里现建的一个浮层——
  ```js
  box.id = 'toastBox';
  box.style.cssText = 'position:fixed;right:20px;bottom:20px;z-index:9999;…'
  ```
  而外壳底栏是 `position:fixed;left:0;right:0;bottom:0; z-index:2147483000`（高约 37px）。
  `bottom:20px` 正好落进底栏那一条，且 `9999 << 2147483000` → 被压在下面。
  外壳注入层给页面留的 `body{padding-bottom:44px}` 只对**普通流**有效，
  `position:fixed` 的元素不认它，所以正文没事、浮层被挡。
* **排查顺便确认**：全 `dashboard.html` 里 `position:fixed` **且带 `bottom`** 的元素
  **只有 `#toastBox` 一个**（扫过一遍），所以修它一个就够；看板本身没有
  "给底栏让位"的概念（`safe-area-inset-bottom` / `bottomBar` 等 0 命中）。
* **改（用户选的方案 1，零改内核）**：
  * 新增 `data\dashboard.patch.css`：`#toastBox { bottom: 52px !important; }`
    （52px ≈ 底栏 37px + 15px 间隙；文件里写清了来龙去脉，方便以后自己调/删）。
  * **顺带把补丁机制改成"每次加载重读"**（带 `(mtime,size)` 缓存）：原来
    `_read_patch` 只在 `WebWindow.__init__` 里读一次，用户改一行 CSS 也得**重启外壳**
    ——而重启会中断内核，为了调个间距付这个代价不合理。现在改完刷新看板即可。
  * 注入层给补丁 `<style>` 固定了 id（`__wb_shell_patch_style__`）并**先删后插**：
    原来每次换页签都会再 append 一份，越堆越多、改规则还可能"看起来没生效"。
* **验**：`ui_api_test.py` 第 2 节（读到/缓存一致/**改文件立刻生效**/超 512KB 被忽略）；
  `probe_menu_live.py` 新增 3 项——补丁 `<style>` 被注入、**只有一份**、

  每次 §2 体检都在误报。此前是我手工跑 `snapshot_core.py` 补的；换个人接手就可能
  被那几行"不一致"吓一跳（交接文档自己写着"留着过期基准比没有基准更危险"）。
* **改（内核零改动）**：`updater.py`
  * 新增模块函数 `write_baseline(core_dir, version, data_dir, note, logger)`：
    与 `tests/snapshot_core.py` 同一件事（`core_manifest(skip_protected=True)` +
    归档旧基准 + 原子写）。
  * `install()` 自检通过、确实装成新版之后调用它，并往 `steps` 里加一行
    「重录只读基准：…」（结果面板能看到）；返回值里多一个 `"baseline": bool`。
  * `rollback()`（手工回滚）成功后同样重录——回滚也是"内核文件被合法换过"，
    不重录就会立刻造出一个"基准说新版、磁盘是旧版"的假不一致。
  * **数据目录用 `self.data_dir`（运行时取），不是 `paths.data_dir()`**：隔离测试
    会把 `self.data_dir` 指到临时目录，于是它**在结构上不可能写坏真基准**。
  * 任何失败只记一行 WARN，**不算更新失败**。
* **验**：`update_isolated_test.py`（改前先看它怎么隔离）：
  * `make_env` 的路径硬化加了 `baseline-core-sha256.txt`——落在测试根之外就直接拒跑；
  * 场景 A 断言：自动重录了基准 / 头里是新版本 / **与升级后的内核逐文件一致** /
    不含 `accounts/` 这类受保护数据 / **旧基准被归档而不是被覆盖**；
  * 场景 D（手工回滚）、E（运行中安装）也各断言了重录成功；
  * 结论一节新增底线：**真基准 sha256 跑完必须一字未变**（实测跑前跑后都是
    `b8f8d4c36e429ca4…`）。全绿。
* **代价/边界**：会多花约 0.1 秒算一遍 44 个文件的 sha256；基准从此"跟着盘走"，
  不再需要人工介入。**要重启外壳才生效**（`updater.py` 是外壳模块）。

## 6. 本轮的坑（含"为什么"）—— 这份文档里最值钱的部分

1. **`ctypes` 不声明 `argtypes` 会炸在很怪的地方**：`LocalFree(blob.pbData)` 传的是 48 位地址的 Python int，
   默认按 32 位转换 → `argument 1: OverflowError: int too long to convert`，而且是在**加密成功之后**、
   释放内存时才炸，看起来像"加密失败"。DPAPI 三个函数都声明了原型。
2. **`merged_effective` 的 `cli` 覆盖只认固定几个键**（`core_dir/port/host/ui/tray_enabled/runtime_dir/
   accounts_dir/usage_dir/lan`）——`panel_password` 不在里面。测试里想给它赋值必须走 `config` 字典。
   （我第一次写端到端测试就在这里栽了：以为内核在用测试密码，其实还在用默认 `admin`，于是断言"门自己关上"失败。）
3. **`Event.wait(timeout)` 超时也会返回**：不看返回值就 `continue` = "每 N 秒自己干一件事"（4.8 那个 bug）。
4. **默认参数在函数定义时就绑定了**：`def f(timeout=RELAUNCH_TIMEOUT)` 之后改模块级常量**不生效**，
   测试想把超时压小必须 `timeout=None` 再在函数里解析。
5. **父进程 `os._exit(0)` 后，经 `powershell &` 拉起的孙子进程活不下来**；直接 `CreateProcess` 一个
   pythonw（GUI 子系统）才行（4.9）。中间那层 console 程序是罪魁。
6. **探针按标题找窗口会认错**：用户开着自己的窗口（同标题）→ 探针发的 `WM_CLOSE` 会去关**他的**窗口。必须按 pid。
7. **探针驱动线程抛异常 = 窗口不销毁 = 进程永久挂着**（`webview.start()` 永不返回）。
8. **`evaluate_js` 的返回值形状不固定**（有时是 JSON 字符串、有时已被解析成对象）：读回来一律"两种都收"，
   别只写 `json.loads`。
9. **探针里 `RESULT = {...}` 这种整体重绑会丢掉之前 `RESULT["x"]=...` 写入的键**（踩过：`panel_calls` 丢了）。
10. **测试会往生产 `shell.log` 写噪音**：`tray_autostart_test.py` 与 `build_shell.ps1`（后者跑 `--print-config`）
    都用真 `data\` 目录记日志。看到日志里冒出"托盘启动失败：模拟 pystray 建菜单失败"别惊慌，那是测试注入的。
11. **`launcher --print-config` 的"开机自启"打的是配置偏好，不是注册表**：注册表里有自启项时它也会显示"未开启"。
    托盘勾选态是直接读注册表的（以注册表为准）。
12. **内核面板会话是内存里的、刻意不落盘** → 任何意义上的内核重启都会让所有浏览器登出（这是作者的安全取舍）。
13. **内核 `/panel/status` 免登录可问**（`panel_password_required` / `panel_password_is_default` / `authenticated`）——
    外壳就是靠它判断"要不要密码、这次窗口登没登录"，别去猜 DOM。
14. **LAN 模式的 banner 在外壳下只进 `data\core-<port>.log`**（外壳捕获内核 stdout），屏幕上只写"（LAN 模式）"，
    而 banner 里有**自动生成的 API Key 和带 key 的看板直链**。要用 LAN 模式就得去日志里搜 `API Key`。
15. **给内核传 `--panel-password` = 每次启动都强制设置面板密码**（会覆盖用户在看板里改的）。
16. **pywebview 的 js_api 回调表是按"文档"存的**（`window.pywebview._returnValuesCallbacks`）。
    页面被替换（导航/重载；**WebView2 的 `chrome-error://` 错误页自己也会重载**）之后，
    在途的那次调用**永远不 resolve**：Python 侧报
    `_returnValuesCallbacks["<方法>"][<id>] is not a function`（那行异常是在 pywebview
    自己的 `_call` 线程里），JS 侧那个 promise 就一直挂着。**所以界面上任何"可选信息"
    都不能挡住主界面**：先把界面开出来，再异步填，并且给 js_api 调用**加超时**
    （`ui_web.withTimeout`）。2026-10-15 实测：设置窗口因此卡成"点了没反应"。
17. **内核的 Key 是"面板优先"**：`wb_proxy.identify_key()` = `extra = () if configured_keys()
    else (API_KEY,)`——看板里一旦有启用的 Key，`--api-key` 与 `wb_settings.ensure_launcher_key()`
    生成的 `launcher_key` **都不再被接受**（内核有意如此）。要判断"别的设备该填哪个"，
    必须按这个规矩算；`settings.json` 里老的 `api_key`/`api_key_set` 是**旧版单 Key 形态**，
    而且内核的 `wb_settings.api_keys()` 读到它时会**迁移并写盘**——外壳读它必须是纯只读，
    别 import 那个函数（`launcher\lanshare.py` 就是自己读 JSON 的）。
18. **探针里 `RESULT = {...}` 整体重绑会把之前写进去的键全丢掉**（§6.9 记过一次，2026-10-15
    又在 `probe_menu.py` 里踩到：新加的键在结论里全是 None，看起来像"功能坏了"）。
    一律用 `RESULT.update({...})`。另外**探针窗口别指向没人监听的端口**：那是 WebView2
    的错误页，会自己重载，把在途的 js_api 调用打掉（自带一个桩页最稳）。
19. **`service.status()["log_file"]` 是打开的文件对象，不是路径**（`service._open_log_file()`
    里 `open(path, "a")`）。把它放进任何 js_api 的返回值里，pywebview 的
    `json.dumps(result)` 会当场抛 `Object of type TextIOWrapper is not JSON serializable`
    ——**整个接口失效**，界面上只看到"报错"或"点了没反应"（2026-10-15 生产实测：
    局域网那一节只剩一句错误提示、连开关都没有）。要路径用 `service._log_path()`。
    ⚠️ 这个坑只在**内核真的被外壳启动过**时出现（不跑时 `log_file` 是 `None`），
    所以"没启内核"的探针抓不到——`lan_share_test.py` 里专门用真文件对象钉了一条。
20. **对话框里的滚动会和后面的看板打架**：用户实测"在设置页来回滑几次就滑不动了"。
    两条一起用才干净：`.body` 上 `overscroll-behavior: contain`（滚到底不接力给看板）
    + 对话框开着时在 **window 捕获阶段**截住 `wheel`（只截发生在对话框里的），
    外加临时把 `html/body` 的 `overflow` 锁成 hidden（关掉时原样还回去）。
    浏览器对 `.body` 的滚动是**默认动作**、不靠监听器，所以截事件不影响对话框自己滚。
21. **`catalog/` 是内核自己会写的运行时存档，别放进"只读基准"**。内核源码里写着
    （`wb_proxy.CATALOG_CACHE_DIR` 上方注释）："每次成功从上游 /v3/config 拉到清单
    就写一份响应体副本，纯留档……与 usage 一样运行时产生……不参与提交与更新"。
    2026-10-15 实测：20:43 录完基准，内核在 20:48/20:53/20:58/21:03 各刷了一次，
    于是基准报"1 处不一致"、看着像**外壳改了内核**——差点误判。处理：把 `catalog`
    加进 `updater.PROTECTED_DIRS`（和 `usage` 同类：更新不覆盖、不进基准），重录基准
    （44 文件 / 0 处不一致），并给 §2 第 7 条加上"列出不一致的文件名"。
    **教训**：基准里只该放"随包静态资产"；凡是内核会自己写的目录，先把它移出去。
22. **"复制"不能指望浏览器那两条路**（用户报障"无法复制"）。`navigator.clipboard.writeText`
    在 WebView2 里可能被权限拦下；而**异步失败之后再退回 `document.execCommand('copy')`
    是错的**——`execCommand` 同样要求"用户手势"，等 Promise 被 reject 时那个手势早就
    过期了，于是两条路一起失败。
    正确顺序（`ui_web.copyText`）：**同步**的 execCommand 先试（此刻手势还在）→
    再试异步 clipboard API → 都不行就交给外壳自己写剪贴板（新增 `launcher\clipboard.py`，
    Win32 ctypes，不看浏览器脸色，`SetClipboardData` 还能返回真假）。
    另外反馈要**就地可见**：按钮自己改成「已复制」，别只写页面底部那行消息——
    用户正看着上面几行，看不到反馈就会以为"没复制上"。
    实测（真 WebView2 + 真剪贴板，先存后还）：剪贴板里确实拿到了那段文字，
    本地那条路就够了（外壳兜底 0 次调用）。
    ⚠️ 连带的纪律：**探针不许动用户的剪贴板**。第一版 `probe_menu.py` 直接点「复制」，
    把假 Key `wb-probe-key` 写进了用户剪贴板（本人当天就踩了）。现在探针先
    `Object.defineProperty(navigator,'clipboard',…)` + 顶掉 `document.execCommand`
    把浏览器那两条路**封掉**，逼出"外壳兜底"那条（由假 api 记录、不真写），
    并在点之前/之后各取一次剪贴板快照，断言"一个字都没变"。
23. **凭据不许"默认带上"**（用户第二次反馈："『复制带 key』为什么会默认带一个 key，
    没有问过我的选择"+"上面的 api 地址也不能复制"）。原来那一节只有**一个**按钮
    （复制带 Key 的看板直链），而 API 地址干脆只是干看着的一行字——两处都是设计问题：
      * **该给选择的给选择**：现在每个地址三个**并列**的动作——「复制 API 地址」、
        「复制看板地址」（都**不含** Key）、「复制带 Key 的直链」（单独一个按钮，
        标签里写明"凭据会进剪贴板与浏览器历史"，屏上只显示 `?key=…`，原文只在
        `data-copy` 里）。
      * **该能复制的都要能复制**：API 基准地址（`http://ip:port/v1`）才是配客户端时
        真正要的那串，它现在有自己的一键复制。
      * `probe_menu.py` 钉了 5 条：API 能复制、看板能复制、**不带 Key 的按钮里一个
        `key=` 都没有**、带 Key 的是单独按钮、标签写明了代价。
    **一般化的教训**：凡是"方便"与"泄露凭据"之间的取舍，默认必须是**不泄露**那一侧，
    并把代价写在按钮上——别替用户选。
24. **`position:fixed` 的浮层不认 `body{padding-bottom}`**。外壳为了给底栏让位，给页面
    设了 `body{padding-bottom:44px}`——那只推**普通流**；`position:fixed` 的元素照样
    贴着视口底边，于是面板自己的通知（`#toastBox`，`bottom:20px;z-index:9999`）
    正好落进外壳底栏（`bottom:0;z-index:2147483000`）那一条里、被压在下面。
    结论：**"给底栏留白"这件事对浮层必须单独处理**（抬 `bottom` 或提层级），
    不能指望留白。而且这类浮层往往**是 JS 现建的**（`toast()` 第一次调用时才建），
    静态搜 CSS 找不到，得搜"创建元素 + 赋 style"的代码（这次是靠"cssText 里同时有
    fixed 和 bottom"扫出来的，见 §4.13）。修它的正确位置是 `data\dashboard.patch.css`
    ——零改内核、内核更新不覆盖。
25. **补丁文件要"每次加载重读"才有用**：`_read_patch` 原来只在 `WebWindow.__init__`
    里读一次，于是"改一行 patch CSS"也要**重启外壳**——而重启会中断内核，为了调个
    间距付这个代价不合理（用户就是这么被卡的）。现在 `api_get_patches` 每次重读
    （带 `(mtime,size)` 缓存，避免每 0.5 秒的状态推送把文件重读一遍）。
    同理，注入补丁 `<style>` 要给**固定 id 并先删后插**：原来每换一次页签就多 append
    一份，越堆越多，改规则还可能因为旧的那份还在而"看起来没生效"。

## 12. 2026-10-18 设置页可折叠分节（手风琴）

> 用户原话："设置页越来越多设置项，翻到下面很麻烦。" 纯前端注入层，零后端改动。

* **做法**：不改那 58 行 `innerHTML`，而是挂载后用 JS 把每个 `<h4>` 连同它后面的
  兄弟节点（含分隔用的 `<hr>`）收进一个 `.sec`；点标题行展开/收起。
  选这条路是因为那段 HTML 由 `panelHtml` / `cands` / `warns` 多处拼接，
  改成嵌套结构容易拼错；而"按 h4 切段"是纯 DOM 操作，**抛异常也只是不折叠**，
  设置页照常能用（外面包了 try）。
* **行为**：
  * 默认**只展开一节**（上次看的那节；没有记录就展开第一节），其余收起 →
    打开设置一屏就能看到全部 4 个标题，不用先滚；
  * 点标题 = 切换，且**排他**（开一节就收起别的，避免又变成"全展开要滚"）；

    `private_mode=False`，能持久；存取失败（隐私模式/存储被禁）就退回默认，不影响折叠；
  * 记录的标题不存在了（改名）→ 兜底展开第一节；
  * 打开时 `scrollTop` 显式归零，避免"上次滚到中间、重开后标题贴边"。
* **关键纪律**：收起的节只是 `display:none`，**节点仍在 DOM 里**——所以
  `#__wb_lan_box__` 这类**异步填充**的容器照样能被 `fillLanBox()` 找到并更新。
  这条专门在测试里钉住了（收起的节里按 id 取元素必须仍在）。
* **验**：
  * `tests\probe_menu.py` 第 7.6 节（真实 WebView2）：分节数量/标题行、

* **边界**：折叠状态是"每台机器 / 每个 WebView2 会话"各存一份，不写 `shell.json`

## 13. 2026-10-19 用户四条反馈的修复

> 全部来自用户实拍截图。**其中第 2/3 条是我上一轮引入的真 bug**，记录如下。

### 13.1 「重启外壳」移到「重启内核」下方

* 原来它跟「设置…」「退出」并排放在最下面，语义上像"设置类"；实际它会让内核短停，
  属于内核/进程操作。移到「重启内核」之后，并单独用分隔线与设置区分开。
* 顺序变成：显示窗口 / 打开看板 → **启动/停止/重启内核 + 重启外壳** → 更新 →
  开机自启 / 打开目录 / 设置… → 退出。

### 13.2 + 13.3 托盘「点此安装」是假把式（**真 bug，我漏的一环**）

* **现象**：托盘显示「有新版 1.7.16 · 点此安装」，点下去只弹一句「请先点『检查更新』」，
  没有任何下一步；底栏那个 `⬆ 1.7.16` 点了也只是打开菜单。
* **根因**：`_install_update()` 只认内存里的 `self._pending_plan`，而这个变量
  **只有本会话里点过「检查更新」才会被赋值**。启动检查 / 周期检查（第 11 节的 A/D）
  只写磁盘账本 `update-state.json`，不写这个内存变量 → 点按钮时 `plan is None`。
* **改**：
  * 新增 `_plan_for_install()`：内存没有就退回 `cached_plan()`（读磁盘账本，**纯本地不联网**）；
    拿到后顺手记回内存，后续「安装更新」项也就可用了。
  * `_install_enabled()` / `_install_label()` 改为看 `_pending_version()`（磁盘缓存也算）。
  * 删掉原来那一项独立的「安装更新」：与首项是同一个动作，菜单里留一行。
  * 菜单标签变成 **「安装新版 X…（内核会重启）」**——代价写在按钮上。
  * 底栏 `⬆ 版本` 点击改为**直接进安装流程**（`updateFlow()` → 带版本号的确认对话框），
    不再只是"打开菜单"。
* **安全性不打折**：缓存 plan 里的 `expected_sha` 是那次检查记下的官方校验值；
  `install()` 仍会重新取官方 digest 校验，不因为走了缓存而跳过校验。

### 13.4 安装前必须确认（用户点名要的）

* **弹不出来就按"取消"处理**——宁可什么都不做，也不替用户点同意（安装会断流）。
* 文案写明代价：「安装会停止内核并覆盖文件，期间模型请求会中断几秒」。

### 13.5 设置对话框高度不再随折叠跳动

* **现象**：展开/收起某一节，整个对话框忽高忽低。
* **根因**：`.box` 只有 `max-height: 86vh`，内容少时盒子就缩。
* **改**：给 `#__wb_settings__ .box` 加 `height: min(86vh, 720px)`，让内部 `.body` 自己滚。

### 10.1 内核守护（`service.py`）——解决"内核崩了没人知道"

* **问题**：`_read_loop` 发现内核退出后只把状态改成 `FAILED`，`tray.refresh()` 每 2 秒
  **只换图标颜色**，不弹提示、也不重启。用户要等客户端报错才知道 8788 断了。
* **改**：
  * `stop()` 在拿锁的状态下先置 `_stop_requested=True`，`_read_loop` 据此区分
    **"用户/外壳要求停的"** 与 **"内核自己没的"**（后者才走守护）；
  * 意外退出 → `_on_core_crashed()`：写 ERROR 日志 + 通过日志订阅者推一行 + 托盘气泡
    （`tray._announce_state_change`）；
  * 自动重启带**退避 5s → 15s → 60s**（`WATCHDOG_BACKOFF`），最多 `core_watchdog_retries`
    次（默认 3，钳制 0..10）；用完就停手并写明"需要人工介入"；
  * 守护线程每轮都复查 `state`/`_stop_requested`：用户中途手动启动/停止就不再插一脚。
* **配置**（`shell.json`，`config.py` 已归一化）：`core_watchdog`（默认 true）、
  `core_watchdog_retries`（默认 3）。
* **界面**：设置页新增「内核守护」一节（开关 + 次数 + 保存即生效，不必重启外壳）；
  后端 `api_watchdog_get` / `api_watchdog_set`（只写外壳自己的 `shell.json`，
  写前留 `config-backups`，值没变不写盘，并同步内存里的 `service.watchdog`）。
* **边界**：`EXTERNAL`（端口上已有外部内核）不参与守护——那不是外壳的孩子，
  拉起来只会打架。

### 10.2 单实例（`paths.py` + `__main__.py`）——解决"两个托盘图标"

* **问题**：`MUTEX_PREFIX` 早就定义了却**没有任何地方用**。开机自启 + 手动双击会各起一个，
  第二个进入"伴随模式"挂着（10-17 生产日志实证：`端口 8788 已有内核，进入伴随模式`）。
* **改**：按**外壳目录**（sha256 前 16 位）命名互斥体：`acquire_single_instance()`；
  拿不到就 `signal_existing_instance()` 置一个命名事件，让第一个实例把窗口叫出来，
  自己 `return 0` 退出。不同目录（生产 / 工作区）名字不同，互不影响。
* **只拦"要常驻"的模式**：`--print-config` / `--selftest` 不抢锁（它们是命令行工具，
  自检还要用隔离端口）。
* **边界**：非 Windows / ctypes 不可用时一律按"单实例继续"，绝不让检测失败变成起不来。

### 10.3 窗口几何（`ui_web.py`）——内嵌看板窗口也记住大小了

* **问题**：`window_geometry` 只有原生兜底窗口读写（`ui_native.py`），内嵌看板窗口写死
  `DEFAULT_SIZE`（实际 **1180×800**），关掉再开就变回去。
* **改**：`_initial_size()` 解析 `"1280x800"`（也接受带位置 `+x+y`，只取宽高）并钳制
  到 880..4096 / 560..4096；`events.resized` 实时记在内存；关窗/退出时
  `save_geometry()` 落盘（值没变不写、写前留 `config-backups`）。
* **刻意不做**：不恢复窗口**位置**——多显示器/拔副屏后容易跑到屏幕外。

### 10.4 三个小瑕疵

* `check_update_on_launch` **不再是死键**：`schedule_launch_update_check()` 延迟 8 秒
  后台静默查一次，**只有发现新版才吭声**（托盘气泡 + 一行日志），绝不自动安装。
* 托盘「启动内核 / 停止内核 / 重启内核」按状态**置灰**（`tray._state_is`），
  不会再出现"点了只回一句已运行"。
* **内核日志轮转**：`data\core-<port>.log` 以前只增不减（已 1.5 MB 且天天涨）；
  现在 8 MB 滚 3 份（`CORE_LOG_MAX_BYTES` / `CORE_LOG_KEEP`）。

### 10.5 为什么这一批值得先做

前三项都是"**断流/重复进程/设置丢失**"这类用户能直接感知的问题；改动集中在
外壳层、不碰内核启动/停止的既有语义（只在"意外退出"这条路上加动作），
回归覆盖到"手动停止不会被误判成崩溃"这一关键反例。
