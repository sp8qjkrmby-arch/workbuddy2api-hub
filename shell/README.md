# WorkBuddy2API-Hub 网关外壳

给 `wb-proxy` 内核套的 Windows 外壳：**一个窗口、一个托盘、一键更新内核**，
而**内核一个字节都不改**。

- **不改内核**：内核文件（`wb_*.py`、`dashboard.html`、`pricing/`、`python/`）
  全部只读对待；外壳只通过命令行参数与它交互。
- **数据不动**：`accounts/`、`usage/` 原地保留，更新时按保护名单跳过。
- **更新有护栏**：官方 SHA256 校验 → 强制备份 → 覆盖 → 自检 → 失败自动回滚。

---

## 一、怎么用

双击 **`启动.vbs`**（零依赖入口，无黑框），或直接跑：

```powershell
runtime\pythonw.exe launcher                     # 默认设置
runtime\pythonw.exe launcher --port 8788         # 换端口
runtime\pythonw.exe launcher --print-config      # 只打印生效配置
runtime\pythonw.exe launcher --selftest          # 自检：启动→探通→停止→复验端口
                                                 # ⚠️ 它会**停掉你给的那个端口上的内核**，
                                                 #    所以务必另给一个隔离端口（见第五节）
runtime\pythonw.exe launcher --tray-only         # 只驻托盘（开机自启用）
runtime\pythonw.exe launcher --no-gui            # 前台守候，Ctrl+C 退出
```

窗口里是**内核看板本体**（账号管理、签到、任务、代理出口、日志一个不缺），
底部一条外壳控制层：

```
[● 运行中  端口 8788 · 账号 9/8 · 内核 1.7.2 · 运行 00:12:34  ⚙]
```

底栏**只有这一条状态**——所有操作都在状态区的**右键菜单**里，不在底栏重复放按钮
（少一处重复就少一处"两处不一致"）。末尾的 `⚙` 是"这里可右键"的提示。

| 操作 | 结果 |
|---|---|
| **左键 / 右键**点状态区 | 打开操作菜单（按状态禁用不可用项） |
| 菜单里的动作 | 都需要你在菜单里再点一次——**点状态区本身不会执行任何动作**，所以不会误触 |

菜单内容与快捷键（焦点在输入框里时不触发快捷键）：

```
已停止 · 端口 8788 · 内核 1.7.2      ← 菜单头：状态 + 端口 + 版本
启动内核                        S
停止内核                    不可用   ← 按状态灰掉
重启内核                    不可用
──────────────────────────────
打开看板（浏览器）              B
检查更新                        U
设置…                                ← 内核位置 + 面板密码，见下
──────────────────────────────
退出                            Q
```

> 「检查更新」是**两步**：先只检查（不动盘），查到新版才弹确认框——框里列出
> 当前/新版本、安装包与体积、校验值来源、更新说明，点「安装并重启内核」才真装。
> 安装期间同一个框显示进度与逐步日志，结束时变成结果面板。
> 详见 [第三节](#三更新内核)。

### 设置…（内核位置 + 面板密码 + 局域网共享）

**两个入口，同一个对话框**：窗口底栏右键菜单里的「设置…」，以及**托盘菜单**里的
「设置…」。托盘那个是为了补一个缺口——`--tray-only`（开机自启那种）起来的外壳
**没有窗口**，窗口里那个菜单根本够不到，于是设置只能靠手编 `shell.json`。
现在点托盘的「设置…」，外壳会**先把窗口建出来，再把同一个设置对话框打开**
（不是第二份设置界面；`data\shell.log` 里会留一行「托盘请求的设置对话框已打开」）。
窗口已经开着时，点它就只是把设置打开，不会多开一个窗口。

**三件事都在里面**，它们都是"配一次、平时不动"的。对话框本身有个规矩：
**标题栏与底部按钮是固定的，只有中间那一段滚动**——所以设置页越长，
关闭按钮也**永远在视野里**（右上角有 `×`，底部有「关闭」，另外 **Esc** 与
**点对话框外面**都能关；四条路走的是同一段代码）。

**① 内核位置**

```
外壳目录：C:\Desktop\wb-shell
当前内核：C:\Desktop\wb-shell\wb-proxy · 版本 1.7.4
认来的途径：外壳的子目录 · 目录完整
记忆文件：C:\Desktop\wb-shell\bootstrap.json（尚未创建）

把内核位置钉下来（以后搬动或同级有多个候选时，外壳不会猜错）：
[ C:\Desktop\wb-shell\wb-proxy                    ]

自动发现的候选（点一下填进输入框）：
[1] C:\Desktop\wb-shell\wb-proxy  外壳的子目录 · 可用 · 当前使用
                                    [校验] [保存并重启外壳]
```

* **钉住位置**：保存后写进 `bootstrap.json`，以后你搬动内核或同级出现多个候选时，
  外壳按你钉的路径走，不会"猜错"；写入后外壳会**自动重启一次**（内核短暂中断约 5 秒）。
* **诊断**：一屏就能看清外壳当前认的是哪个目录、从哪认来的、还有哪些候选。
* **⚠️ 它救不了"外壳起不来"那种情况**：找不到内核时外壳会在启动阶段就退出，
  那种状态下**没有底栏、没有菜单可点**。那种情况用启动参数救：
  `启动.vbs --core-dir D:\somewhere\wb-proxy`（或直接改 `bootstrap.json`）。

**② 面板密码：记住它，就不用每次重开窗口都输**

```
面板是否需要密码：需要
已记住密码：否
[x] 记住面板密码（重开窗口 / 重启内核后自动登录）
密码用 Windows DPAPI 按当前用户加密存放（data\panel-password.sealed），不进日志；
换个 Windows 用户或换台机器都解不开。勾上之后第一次仍需你手输一次，外壳会把它记下来。
代价说清：勾上之后，"能打开这个窗口的人"就等于能进面板（本机这道门不再拦人）。
                                    [忘记已记住的密码]
```

**为什么需要它**：看板登录成功后拿到的 token 存在**页面自己的 `sessionStorage`**
里，而外壳的 `×` 是**销毁窗口**（pywebview 拦不住关闭，见下），托盘「显示窗口」是
**重建一个新窗口**——token 属于"上一个窗口"，自然就没了。更要命的是 token 在
**内核内存**里，**内核一重启必然失效**（内核作者明确说这是有意的安全取舍：
*"restarting the gateway logs browsers out, which is the safer default for a LAN tool"*）。
所以"记住"能记的只能是**密码**，在门出现时替你输一次。

三条自律（都能在这份代码里核对）：

* **不勾就绝不记**：开关默认关；关着时取口令的接口一律拒绝；
* **加密存放**：DPAPI（当前 Windows 用户作用域），文件被拷走也解不开，且**不进日志**；
* **只试一次**：每次页面加载只自动登录一次（内核限流 5 次/60 秒），失败就老实退回手输。

**③ 局域网共享（LAN 模式）：让手机/另一台电脑也能用这个网关**

```
运行中的内核：否：只监听 127.0.0.1（别的设备连不上）
外壳配置：关闭
[x] 允许局域网内其它设备访问（LAN 模式）——开启后内核会强制要求 API Key

本机内网地址（别的设备用这些）。默认不带 Key：API 地址与看板地址都能一键复制，两个都不含凭据。
[1] 192.168.31.25
API 地址：http://192.168.31.25:8788/v1            [复制 API 地址]
看板地址：http://192.168.31.25:8788/              [复制看板地址]
带 Key 的看板直链：http://192.168.31.25:8788/?key=…  [复制带 Key 的直链]
    只有点这个才带上 Key。它会替你填好看板里的 Key，代价是凭据会进剪贴板、
    也可能进浏览器历史——不想留痕就用上面两个。

别的设备要填的 API Key（来源：看板里配置的 API Key（2 个可用））：
手机：      [ wb-abc…xyz9 ] [显示] [复制]
平板：      [ wb-def…uvw8 ] [显示] [复制]
风险：谁拿到这个 Key，谁就能花你账号的额度。
不要把 8788 映射到公网：LAN 模式是给同一个局域网用的，暴露到公网等于把额度交给互联网。
别的设备连不上，多半是 Windows 防火墙没放行：在内核目录里以管理员身份运行 allow-firewall.bat …
                    [只保存（稍后自己重启内核）] [保存并重启内核]
```

* **开关写在哪**：`data\shell.json` 的 `lan`（外壳自己的配置），**内核一个字节都不改**；
  真正生效是外壳下次启动内核时多传一个 `--lan`（内核自己会切成 `0.0.0.0` 并**强制要求 API Key**）。
  所以改完**要重启内核**才生效——对话框里给了「保存并重启内核」这一键（会先问一句，
  因为内核会中断几秒、面板要重新登录）。
* **该填哪个 Key 是算出来的，不是猜的**：内核的规矩是"**看板里一旦有启用的 Key，
  就只有那些 Key 被接受**"，启动参数里的 key 与自动生成的 `launcher_key` 都会被忽略
  （内核刻意如此，免得老 key 在面板收紧之后还管用）。所以这一节显示的是**真正管用的**
  那个（或那几个）Key，旁边写明来源；不在此列的会说明"为什么它不被接受"。
* **Key 默认打码**，点「显示」才展开（跟内核看板自己的习惯一致，截图不泄露）。
* **凭据绝不默认带上**：API 地址、看板地址各自一个「复制」，**都不含 Key**；
  带 Key 的看板直链是**单独一个按钮**（屏上只显示 `?key=…`，原文只在该按钮的数据里），
  标签里写明代价（凭据会进剪贴板与浏览器历史）。要不要把凭据放进剪贴板，
  **由你点哪一下决定**，外壳不替你默认。
* **「复制」为什么一定管用**：浏览器那两条路（`navigator.clipboard`、`execCommand`）
  在 WebView2 里都可能失败，而且"异步失败后再退回 execCommand"会丢掉用户手势、
  一起失败。所以顺序是 **同步 execCommand → 异步剪贴板 API → 外壳自己写剪贴板**
  （Win32，不看浏览器脸色）；按钮会就地变成「已复制」告诉你成了。
* **连通性自检**：外壳会真的从内网地址问一次 `/health`——"配置里写着 lan=true"不算数，
  防火墙照样能把包丢掉，所以这一条是**端到端**的证据。
* **不做公网端口映射**；一旦暴露到公网，等于把额度交给互联网。别人拿到 Key 同理。

点别处或按 **Esc** 关闭菜单（设置对话框开着时，Esc 关的是设置）。托盘不可用时 `×` 仍会先确认再退出（见下）。

**关闭语义（三个入口分得很清）**：

| 入口 | 行为 |
|---|---|
| 窗口右上角 **×** | **只关窗口**：窗口销毁，外壳留在托盘，**内核继续服务**。点托盘「显示窗口」重建窗口。 |
| 控制层 / 原生窗口 **退出** | 停内核 + 停托盘 + 结束外壳 |
| 托盘右键 **退出** | 同上 |
| 托盘 **显示窗口** | 窗口关掉了就重建一个（会重新加载看板），还在就只唤起 |
| 企业环境下没有托盘可用时 | × 会先问一句再退出（没有托盘就没法把窗口找回来） |

> **开机自启（`--tray-only`）那种启动方式下，外壳一开始没有窗口**，这时
> 「显示窗口」的语义是**把窗口建出来**：外壳就地转为带窗口模式，内核照常服务
> （不重启、不中断）。窗口建好之后再看这一项，才是上表说的"重建/唤回"。
>
> **关掉的窗口不会自己回来**（除非你点「显示窗口」）。这条曾经是坏的：等托盘
> 召唤用的是 `Event.wait(600)`，而 `wait()` **超时也会返回**，代码没看返回值就
> 接着 `continue`，于是"关掉窗口 10 分钟后自己弹回来"——2026-10-14 生产日志里
> 21:46:59 关窗、21:56:59 自己开窗，正好 600 秒，那一轮**没有任何托盘请求**。
> 现在超时只是再等一轮，并且由 `tests/probe_no_self_reopen.py` 钉住。

> 实现上有一点值得记下来：pywebview 6.2.1 的 `closing` 事件**返回值无效**——
> `Event.set()` 在子线程里收集处理函数返回值，却在主线程紧接着读取，集合永远为空，
> 所以"取消关闭"不可能生效（`tests/probe_closing.py` 三种写法实测都无效）。
> 因此外壳**不假装能拦**：× 就是真关窗口，由 `ui_web.WebWindow.run()` 的窗口
> 生命周期循环决定"重建还是退出"（`tests/probe_recreate.py` 证明同进程可重复
> `create_window` + `start`）。

> **外壳刻意不重复内核已有的功能。** 复制 API 地址、复制 API Key、账号备注都由
> 内核看板自己提供——网关页的「复制」按钮（`copyAgentUrl`）、设置 → API Key 的
> 「复制」（`copyKeyRow`）、账号行的备注按钮。外壳只保留内核对等能力之外的那部分：
> **进程启停、检查更新、退出**。少一份重复实现，就少一份"两处不一致"的可能。
> （早期版本曾在控制层放过这三个按钮，已移除。）

### 界面降级链

外壳永远优先"能用"，而不是"好看"：

| 情况 | 行为 |
|---|---|
| WebView2 可用（默认） | 单窗口内嵌看板 + 控制层 |
| WebView2 缺失 / 被企业策略禁用 | 自动切**原生窗口**（tkinter），看板走系统浏览器 |
| 原生窗口也不可用 | 退回**命令行模式**，内核照常服务 |
| 托盘依赖不可用 | 托盘静默禁用，窗口与内核不受影响 |

每次降级都会在 `data\shell.log` 里写明原因，不会静默变样。

## 三、更新内核

两个入口，**都是"先检查、再确认"两步，绝不自动安装**：

| 入口 | 怎么操作 |
|---|---|
| 窗口底栏菜单 | 点「检查更新」→ 有新版就弹出确认框 → 点「安装并重启内核」 |
| 托盘菜单 | 点「检查更新」→ 菜单里多出一项「安装更新 vX.Y.Z」→ 点它 |

确认框里会列清：当前/新版本、安装包名与体积、**校验值来源**、更新说明，以及
"安装会先停止内核（本机短暂中断）"的提示。**不能安装的情况会当场说明原因**
（内核是外部启动的、端口上另有内核在跑、取不到官方校验值、包缺必需文件），
那时框里只留「关闭」——不会让你下完几十 MB 才被拒绝。

安装期间同一个框变成进度视图（阶段 + 百分比 + 逐步日志），结束时就是结果面板：
成功 / 失败但已自动回滚 / 未完成，附最后 12 步；完整步骤在 `data\shell.log`。

**更新成功之后**，结果面板会问你接下来怎么办（三个选择，都不是必须做的）：

| 选择 | 做什么 | 代价 |
|---|---|---|
| 稍后手动 | 什么都不做 | 无（下次打开窗口就是新界面） |
| 重新加载看板 | 只重新加载窗口里的看板页 | 无（**内核不动**，几秒） |
| 重启外壳 | 停内核 + 停托盘 + 换一个新外壳进程 | 内核短暂中断（几秒） |

为什么"内核已经是新的了，还要选"：安装的最后一步已经**按新版本重启过内核**，
外壳也会自己刷新版本号（见下）。真正还旧的是**这个页面**——它还是旧内核给它的
HTML/JS，所以「重新加载看板」才是让新界面出现的那个动作。
「重启外壳」是给"想要一个从代码到界面都重新开始的外壳"准备的，**不是必需的**；
托盘菜单里也有一项「重启外壳」，用在从托盘装完更新的场合。

> 这里曾经有个坑（2026-10-14 实测）：**内核版本号是外壳构造时读一次就缓存住的**，
> 于是更新完之后底栏、菜单、「检查更新」里的"当前版本"一直报旧号，看起来像
> 更新根本没装上去——用户只能去重启内核、再重启外壳。现在 `service.status()`
> **每次状态刷新都重新确定版本**（`/health` 报了就用它，否则读盘，带 mtime 缓存），
> 内核一换文件界面立刻跟上；每次内核启动也会把版本写进日志：
> `内核已就绪：账号 9 个（可用 9），版本 1.7.4`。

想先确认当前状态健康，或干脆不用界面：

```powershell
runtime\pythonw.exe launcher --selftest --port 18788   # 启动→探通→停止→复验端口
```

> ⚠️ `--selftest` 第 3 步会**停掉它用的那个端口上的内核**，而端口来自配置
> （默认 8788）。所以自检一定要显式给一个隔离端口，别对着正在服务的那一个跑。

更新流程（9 步，任一步失败即中止并保持现状）：

1. **下载** `workbuddy2api-hub-vX.Y.Z.zip` 到 `data\staging\`。这一步带**下载护栏**：
   - **核对字节数**：拿到的比元数据里的体积少就**不算成功**——截断必须在这里报出来；
   - **断点续传**：中断后带 `Range` 从断点接着要（GitHub 直链实测支持 206），
     一次抖动只损失没传到的那一小段；最多 4 次，间隔 2/4/6 秒；
   - 怎么也补不回来时报的是「**下载不完整：x MB / y MB**」，
     而不是让人误以为是包有问题；
2. **校验**官方 `SHA256SUMS`；取不到时回退用 GitHub releases 元数据里的官方
   `digest`（国内网络下直链抖动是常态）；两者都没有就**拒绝安装**。
   校验不过时消息里会带上**包体积**，并区分两种情形：体积也不对（下载不完整）
   vs 体积对但内容不同（更像内容被替换）；
3. **安全解压**到 `data\staging\`（拒绝绝对路径、`..`、符号链接），只取顶层
   `wb-proxy/`；解出来的包缺必需文件也在这里就中止；
4. **停内核**并确认端口真的释放。**只有到这一步才需要内核让路**：前 3 步只碰
   `data\staging`，所以内核只在备份/覆盖那几秒下线，而不是整段下载时间
   （9.9 MB 实测要下 60~90 秒）。下载失败时内核**压根没停过**；
5. **强制备份**现内核到 `data\backups\core-<版本>-<时间>.zip`（含逐文件
   `__manifest__.json`）——备份失败就不继续（并立刻把内核放回去）；
6. **覆盖**，命中保护名单的跳过并单独列出；
7. **自检**：按原参数重启内核并探通 `/health`；
8. **失败自动回滚**：逐文件还原 + 重启旧内核；回滚也失败时给出备份路径与手动命令，
   **绝不静默留一个半覆盖的内核**；
9. **重录只读基准**（`data\baseline-core-sha256.txt`，旧的那份归档到
   `data\config-backups\`）。**只在自检通过、确实装成新版时才做**（回滚路径不碰它）。
   为什么要有这一步：内核被合法换过之后，那份"证明外壳没改过内核"的基准就过期了
   ——留着它，下一次体检会把**升级**报成**外壳改了内核**。手工回滚（下面那条）成功后
   同样会重录，否则立刻又会出现"基准说新版、磁盘是旧版"的假不一致。

> **关于镜像（`update_mirror`）**：它只用来**下载包**。校验值优先取
> `api.github.com` 里 releases 元数据的 `digest`（这个响应不经镜像），
> 所以在配了镜像的情况下"官方 SHA256 校验"依然成立。只有当官方 API 也取不到
> 摘要、只得退用镜像提供的 `SHA256SUMS` 时，来源会被**如实标成"镜像提供的"**
> 并附一句提醒——因为那种情况下镜像能同时改包和校验值。

### 保护名单（这些路径永不被覆盖）

`accounts/`、`usage/`、`catalog/`、`python/`、`tests/`、`.git/`、`data/`、`__pycache__/`、
`*.log`、`*.pyc`

三条值得说明的取舍：

- **`python/`（便携运行时）不替换**：换解释器风险高于收益；新包声明的运行时版本
  与你本地不一致时会在更新日志里**明确提示**，而不是悄悄跳过。
- **`catalog/` 不替换**：它是**内核自己会写的运行时存档**（内核源码里写着
  "每次成功从上游 /v3/config 拉到清单就写一份响应体副本，纯留档……与 usage 一样
  运行时产生……不参与提交与更新"），和 `usage/` 同类。它原先漏在名单外，副作用是
  **只读基准会被它污染**：录完基准十几分钟后内核自己刷新一次
  `catalog/product-config-cn.json`，基准就报"1 处不一致"，看着像外壳改过内核。
- **旧版已删除的文件不自动删**：磁盘上多出来的东西无法与你的手改区分，
  只列出来让你自己决定。

## 四、托盘与开机自启

**托盘菜单**：状态行（只读）· 显示窗口 · 打开看板 · 启动/停止/重启内核 ·
检查更新 · **安装更新 vX.Y.Z**（检查出新版后才可用，标签里带版本号）·
**开机自启（勾选态）** · 打开数据目录 · 打开内核目录 · **设置…** ·
**重启外壳** · 退出。

> 「重启外壳」= 停内核 + 停托盘 + 换一个新外壳进程（约几秒后自己回来）。
> 与窗口里的「内核位置」改动走**同一条重启链路**（`_spawn_replacement_shell`）。
> 更新之后想要一个"从代码到界面都重新开始"的外壳时用它；**单纯为了版本号
> 显示正确是不需要的**——那个外壳自己会刷新（见第三节）。
>
> 这条链路曾经是**坏的**（2026-10-14）：老写法用 `powershell -Command "Start-Sleep …;
> & pythonw …"` 包了一层，而父进程紧接着 `os._exit(0)`——实测被 powershell 拉起的
> 孙子进程**活不下来**，于是"重启"的实际效果是"内核停了、外壳也没了"（生产日志里
> 21:41:05 点重启 → 21:42:52 才起来，还是人手动开的）。现在直接 CreateProcess 一个
> pythonw（GUI 子系统，不依赖父进程活着），并且**确认新外壳打出启动日志之后**当前
> 进程才退出；确认不了就重试、失败则弹框告诉你手动启动，绝不假装成功。
> 由 `tests/relaunch_test.py` 钉住。

> 托盘没有对话框，所以进度体现在**悬停文字**上（`WorkBuddy 网关 — 更新中：…`），
> 结果用气泡报一句，完整步骤在 `data\shell.log`（气泡显示不下多行文本）。

「显示窗口」在**开机自启那种只驻托盘、还没建窗口**的状态下，是"现在把窗口建出来"
（外壳就地转为带窗口，内核不受影响）；窗口已经建过之后，它才是"唤回/重建"。
设置里 `start_minimized=true` 不会拦住这一项——你点它就是要看见窗口。
没有界面可显示时（命令行守候模式）它会明确告诉你，而不是点了没反应。

「设置…」在同一种状态下也是"**先把窗口建出来**，再把设置打开"——你点的就是要看设置，
所以 `start_minimized=true` 同样不拦（窗口不出来的话，设置等于没开）。
没有设置面板可显示时会**明说**：命令行守候模式提示"当前模式没有设置面板"，
原生窗口兜底（tkinter 那种界面里确实没有设置面板）提示去改 `data\shell.json`
或把界面切成内嵌看板——都不会点了没反应。

**开机自启**写在 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`
（纯用户级，不需要管理员）：

```
"<shell>\runtime\pythonw.exe" "<shell>\launcher" --tray-only
```

- 勾选态**以注册表为准**——你在注册表编辑器里手删了，界面就显示未勾选；
- 写入后**读回核实**，失败（组策略禁用 Run 键等）会如实报错；
- **路径漂移自愈**：外壳被挪过位置后，启动时会提示并一键修正。

## 六、加自己的 UI（不挡内核更新）

三种方式，从轻到重：

1. **原生控制条**：直接改 `launcher\ui_web.py` 里的 `CONTROL_BAR_JS`。
   它是自包含的一段 JS + 内联样式（只在自己的 `#__wb_shell_bar__` 里生效），
   加按钮只要往 `build()` 的 `innerHTML` 里塞一个，再在点击分发里接一句
   `call('你的方法', payload)`；后端在 `WebWindow` 上加同名 `api_xxx(self, payload=None)`
   并在 `run()` 里挂到 `api` 对象上即可。
   ⚠️ **方法签名必须带 `payload=None`**：pywebview 调 js_api 时会多传一个位置参数，
   签名不匹配的异常只在 stderr 留一行，界面上表现为"点了没反应"。
   `tests\check_js_api.py` 就是钉这条契约的。
2. **看板补丁**：写 `data\dashboard.patch.css` / `data\dashboard.patch.js`，
   外壳会在看板加载后注入。**不要直接编辑内核 `dashboard.html`**——
   那样内核一更新就被覆盖。补丁**每次加载都重读**：改完只要刷新看板（关掉窗口再点
   托盘「显示窗口」，或重新加载看板）就生效，**不必重启外壳**（重启会中断内核）。
   外壳自带一条现成的补丁：把面板自己的通知抬出外壳底栏
   （`#toastBox { bottom: 52px }`，见下），想改间距或删掉都行。
3. **内核自带能力优先**：复制 API 地址 / API Key、账号备注、日志复制等已经在内核
   看板里，直接用它。外壳只补内核没有的（进程生命周期、更新、托盘）。

**托盘菜单要加项**：改 `launcher\tray.py` 的 `_build_menu()`，动作走 `self._work(名称, 函数)`
丢到工作线程——菜单回调里绝不要直接调阻塞函数（`stop()` 最长等 8 秒、`check()` 要联网）。

注入层全部包在 try/catch 里：内核看板改版导致选择器失配时，只是"某个按钮不出现"，
**不会损坏看板，也不会影响内核**。

## 七点五、把内核搬进外壳里（或搬到别处）

自动发现按「越贴身越优先」找内核，三处都认：

1. **外壳的子目录**：`wb-shell\wb-proxy\`（推荐，最不容易被误删）
2. **外壳的兄弟目录**：`C:\Desktop\wb-proxy\`
3. 外壳所在目录的**上一层的兄弟目录**（多一层容错）

任一处放了含 `wb_proxy.py` **且**含 `dashboard.html`（或 `python\`）的目录就能被认出来。

搬动的正确顺序（**关键：先停内核**）：

```
1. 先从托盘「退出」或外壳「停止内核」，确保端口释放
2. 再移动目录（Windows 上文件被运行中的内核占用会导致移动失败/搬一半）
3. 双击桌面「WorkBuddy 网关」即可，外壳会重新发现内核
```

搬完若外壳报「没找到内核目录」，两种可能：

* 内核放在了不认识的位置 → 用 `--core-dir <路径>`，或写 `bootstrap.json`
  （`{"core_dir": "D:\\somewhere\\wb-proxy"}`）；
* 或者搬动时**内核还在跑**，文件被占用导致只搬了一半 → 先停内核再搬。

> 早期版本的自动发现**只看外壳的兄弟目录、不扫子目录**，所以把内核搬进外壳后
> 会报「没找到内核目录」。已修（`paths.find_sibling_core` 现在三处都扫）。

## 七点六、两个实例别并存

同一套内核只能有一个外壳在管。若内核是**别处启动**的（例如你直接双击了
`wb-proxy\start-wb-proxy.bat`，或另一个 cmd 窗口里的 python 进程），外壳启动时会
探到 8788 已有内核，于是进入**伴随模式**：

| 伴随模式下 | 结果 |
|---|---|
| 看板、复制地址、查看状态 | 正常 |
| 「停止内核」/「重启内核」 | **无效**（那内核不是外壳启的，它不越权去停） |
| 「检查更新 / 安装更新」 | **安装会被拒绝**（提示"停止后端口仍被占用"）——它不会在文件被占用的内核上覆盖 |

要让外壳完整接管，先关掉那个启动内核的窗口，然后只用桌面快捷方式启动。

## 八、已知限制

- **本机主路径**用 `runtime\` 里的 Python 3.14（带 tkinter 与 WebView2 依赖）。
  内核便携包里那份 3.12 **没有 tkinter**，也不带 3.12 版的 `_cffi_backend`，
  所以它只能跑内核、不能跑 GUI——外壳因此自带运行时。
- **面板登录态**靠 `data\webview-profile` 持久化。清掉它会要求重新登录面板。
- **开机自启只实现了 Windows**；macOS（LaunchAgents）与 Linux（XDG autostart）
  在 `autostart.py` 里留了接口并明确标注未实现。
- **旧版残留文件不自动删除**，更新后会列出来供你确认。
- **托盘/WebView2 依赖第三方**（pystray + Pillow、pywebview），但都是随壳分发、
  运行时不联网装包；升级依赖 = 整块替换 `launcher\vendor\`，本身可回退。

## 九、排障

| 现象 | 先看哪里 |
|---|---|
| 窗口一闪而过 / 没窗口 | `data\shell.log`，搜"降级" |
| 内核起不来 | `launcher --selftest --port <隔离端口>`，会打印内核日志尾部 |
| 端口被别的程序占了 | 外壳会区分"我们的内核"与"别的 HTTP 服务"并给出提示 |
| 托盘没图标 | `data\shell.log` 搜"托盘未启用" |
| 托盘「显示窗口」没反应 | 第四节：托盘模式下它是"把窗口建出来"；命令行守候模式会明确告知没有界面 |
| 每次重开窗口/重启内核都要输面板密码 | 内核的会话在内存里、重启必然登出（有意设计）。用「设置…」→ 记住面板密码，见第一节 |
| 更新报「下载不完整 x MB / y MB」 | 网络把直链切断了（外壳已自动续传重试 4 次）；稍后再试，或在设置里填 `update_mirror` |
| 更新报「SHA256 校验不通过」 | 消息里有包体积：体积不对=下载坏了；体积对但哈希不对=内容不是官方那一份，别装 |
| 更新完界面还显示旧版本 | 已修（外壳现在每次状态刷新都重读版本）。权威记录是 `data\shell.log` 里的「内核已就绪：… 版本 x.y.z」 |
| 想看内核原始输出 | `data\core-<端口>.log` |
| 想确认外壳没改内核 | 与 `data\baseline-core-sha256.txt` 比对。注意基准**不含**运行时数据（`accounts/`、`usage/`、`catalog/`）——那几处的变化是内核自己在写，不是外壳 |
| 局域网里别的设备连不上 | 先看「设置…」→ 局域网共享里的**连通性自检**（那是真探过 `/health` 的）；没应答就先确认 `lan` 开着**且已重启内核**，再看防火墙（内核目录里的 `allow-firewall.bat`） |
| 「局域网共享」那一节显示"读取失败…" | 点那一节的「重新读取」。这不是设置坏了，只是那一段信息没取到（设置页故意做成"先开界面、后填那一节"，取不到也不影响上面两节）；一直失败就看 `data\shell.log` |
| 设置页里滚着滚着滑不动了 / 滚动漏给后面的看板 | 已修：对话框里的滚动与看板隔离（滚到底不接力给看板，滚轮也不传给看板的处理函数）。若还复现，记下是"滑几次之后"还是"一开始" |
| 点「复制」没反应 / 复制不出来 | 已修（外壳自己写剪贴板，见第一节「局域网共享」那条）。按钮会就地变成「已复制」；若显示「复制失败」，把 `data\shell.log` 里「复制到剪贴板：失败」那几行贴出来 |
| 面板自己的提示（"设置已刷新"那种）被底部状态栏挡住 | 已修：面板的通知是 `position:fixed;bottom:20px` 的浮层，而外壳底栏是 `bottom:0` 且层级更高，所以正好被压住（页面留白只对普通流有效，浮层不认）。现在用 `data\dashboard.patch.css` 把 `#toastBox` 抬到 `bottom:52px`——想调间距或去掉就改/删这个文件，**不用重启外壳**，刷新看板即可 |
| 别的设备要填哪个 API Key | 「设置…」→ 局域网共享里那个（**默认打码，点「显示」**）。注意：看板里配过 Key 时，**只有那些 Key 管用**，启动参数/自动生成的 key 会被忽略——界面上会写明 |
| 局域网共享开了但界面还是"只监听本机" | `lan` 只是"偏好"，要**重启内核**才生效；另外若启动参数里带了 `--lan`/`bootstrap.json` 提供了它，那个优先，界面会当场说明并拒绝改配置 |
